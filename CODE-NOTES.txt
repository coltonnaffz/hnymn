HNYMN APP - CODE NOTES
=====================

Purpose
-------
This guide describes how index.html, login.html, style.css, Supabase, and the
offline service worker fit together. It is intended as a map for learning the
code, not as a replacement for the source comments.

The stylesheet in this project is named style.css (singular). There is no
styles.css or login-html file; this guide uses the actual filenames.


How a browser request moves through the app
-------------------------------------------
1. The browser opens index.html, loads style.css, the Supabase JavaScript
   library from its CDN, and data/supabase-client.js.
2. supabase-client.js creates the shared client named sb. Both HTML pages load
   the same client so they see the same persisted Supabase login session.
3. index.html asks Supabase for the saved session with sb.auth.getSession().
   If signed in, it loads the content, checklist, and image URLs, then renders
   the app. If signed out, it navigates to login.html.
4. When the app is offline and a saved content snapshot exists, index.html
   displays that snapshot in read-only mode instead of sending the visitor to
   the login page.
5. login.html checks for an existing session. If one exists it returns to
   index.html. Otherwise, submitting the form calls Supabase password sign-in.
   Successful sign-in returns to index.html; a failed sign-in stays on the form.
6. The Sign out button on index.html signs out, clears private cached app data,
   and navigates back to login.html.

In short:
  index.html -> (no session) -> login.html
  login.html -> (successful sign-in) -> index.html
  index.html -> (sign out) -> login.html

The pages use relative paths, so they should be deployed together with the
data folder, style.css, and sw.js at the same site root.


Where the data comes from
-------------------------
- Supabase Auth identifies the visitor. The role in user app_metadata controls
  whether editor-only controls are shown.
- The Supabase "content" table stores the trip content as key/value records.
  loadCloudContent() reads those records and applyContent() assigns each key
  to the matching in-memory data variable.
- The "checklist" table stores bucket-list and animal checks.
- The private "gallery" Storage bucket holds uploaded photos; the public
  "site-assets" bucket holds app illustrations. Gallery photos use signed
  URLs, while illustrations use public object URLs.
- localStorage keeps a last-loaded content snapshot and checklist state for
  offline use. It is a cache, not the authoritative database.
- sw.js caches the app shell and image bytes to improve offline behavior.

When editing, the app changes itineraryDraft in memory. commitDraftChange()
refreshes the affected views and calls saveItineraryToCloud(). The editor also
has an explicit Save changes button that flushes the itinerary and checklist.
Checklist changes are mirrored locally and queued for retry when offline.

Main page: index.html functions
-------------------------------

Authentication and page state
- applyRole(session): reads the user's role and sets role-editor or role-viewer
  on the body. CSS uses these classes to gate editing controls.
- showApp(session): loads the content and supporting state, rebuilds the
  working itinerary, renders the views, and shows Sign out for signed-in users.
- offlineFallbackOrHome(): opens cached content read-only when offline, or
  sends signed-out visitors to home.html.
- sign-out click handler: calls Supabase sign-out, clears local private caches,
  and routes to home.html.
- getSession promise handlers: restore a saved login session and choose the
  app or welcome page.

Cloud content and rendering
- applyContent(byKey): copies Supabase content values into app data variables.
- loadCloudContent(): fetches the content table; falls back to the local
  snapshot if the network request fails.
- reseedWorkingState(): creates a fresh editor draft from saved itinerary data.
- renderAll(): refreshes all app sections after content is ready.
- renderSite(): fills the hero, hotel card, and footer from site data.
- renderSite's set(id, val, asHtml) helper: updates a page element as text, or
  as HTML for configured rich-text fields.
- renderPreview(): creates the Preview image sections.
- escAttr(value): escapes text for use inside generated HTML attributes.
- escHtml(value): escapes text for use as generated HTML content.

Checklist and offline behavior
- loadChecklistState(): reads checks from Supabase and preserves unsynced local
  changes when available.
- saveChecklistState(): mirrors checklist changes locally and writes to
  Supabase, leaving a dirty marker when a retry is needed.
- flushChecklistQueue(): retries the checklist write after connectivity returns.
- updateOfflineBanner(): synchronizes the offline banner and body CSS class.
- online event handler: updates the banner and retries pending checklist data.
- offline event handler: updates the banner when the browser disconnects.

Itinerary persistence, photos, and media
- currentItineraryValue(): packages the current days and unassigned items in
  the shape stored in Supabase.
- saveItineraryToCloud(): writes the itinerary for editor-role users.
- renderGallery(): loads gallery rows, creates signed URLs, and renders photos.
- handleGalleryUpload(files): uploads selected images and their metadata.
- editGalleryCaption(id, button): edits and saves a gallery photo caption.
- allMediaPaths(): collects the unique image paths used in Preview and Animals.
- loadMediaUrls(): builds public URLs for Preview and Animal images.
- warmMediaCache(): fetches image URLs in the background for the service worker.
- mediaUrl(path): returns the public URL for a path, or the original path.

- toggleDay(card): opens or closes an itinerary day card.

- foodIconById(id): gets a food icon or a category-based fallback icon.

Login page: login.html handlers
-------------------------------
- Existing-session promise handler: sends an already authenticated visitor
  directly back to index.html.
- Existing-session error handler: writes session restoration errors to console.
- Login form submit handler: prevents ordinary form navigation, signs in with
  email/password, shows errors, and returns to index.html after success.
- Password visibility click handler: switches the password field between
  masked and visible text and updates its accessible label.

These handlers are anonymous functions (callbacks), not separately named
functions. The same pattern is used for map/filter/forEach callbacks in
index.html: the surrounding function comment explains the work they perform.


How style.css participates
-------------------------
style.css contains presentation only; it does not fetch data or route pages.
Its sections are organized around the page header, tabs, itinerary/activity
cards, food, gallery/lightboxes, the staging editor, and the login page.
The body classes role-editor, role-viewer, no-session, offline, and editing are
set by JavaScript and control what the visitor sees or can do.


Terms worth recognizing
-----------------------
- DOM: the browser's in-memory representation of the HTML page.
- Session: Supabase's authentication state for the current visitor.
- Promise/async/await: JavaScript's way to wait for network or other delayed
  work without freezing the page.
- Callback: a function passed to another function to run later or once per
  event/item (for example, a click handler or an array map callback).
- Render: build or update visible HTML using current app data.
- Signed URL: a time-limited URL that grants access to a private Storage file.
- Row Level Security (RLS): Supabase database/storage rules enforced by the
  server. Hiding editor controls in CSS is not a substitute for RLS.
- localStorage: browser storage used here for offline snapshots; it is not the
  shared source of truth and should not contain secrets.


Configuration reminder
----------------------
data/supabase-client.js must contain the correct Supabase project URL and
anon/public key. The anon key is intended for browser use, but access must be
restricted with Supabase RLS policies. Never put a service_role key in browser
code. If the key in the actual file is literally "******", the Supabase client
cannot authenticate correctly.
